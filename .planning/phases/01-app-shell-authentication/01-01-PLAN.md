<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser localStorage | JWT readable by any same-origin script — XSS risk |
| Browser → NestJS API | Credentials and tokens over HTTP in local dev; HTTPS in production |
| RTK Query fetch | Response bodies parsed as JSON — no eval |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | localStorage djosu_access_token | accept | Accepted for v1 per D-01; document XSS hygiene — no dangerouslySetInnerHTML, sanitize user-derived display only |
| T-01-02 | Spoofing | POST /api/auth/login | mitigate | HTTPS in prod; client sends only email/password JSON; no token in URL |
| T-01-03 | Tampering | baseQuery 401 handler | mitigate | clearSession + redirect prevents stale token reuse; do not retry login automatically |
| T-01-04 | Repudiation | — | accept | No audit log in frontend MVP |
| T-01-05 | Denial of Service | — | accept | Out of scope Phase 1 |
| T-01-06 | Elevation | AuthGuard client-only | mitigate | Backend JwtAuthGuard remains source of truth; UI guard is UX only — API calls without token still 401 |
| T-01-SC | Tampering | npm deps (@reduxjs/toolkit, react-redux) | mitigate | Packages already in lockfile; no new installs this plan |
</threat_model>
